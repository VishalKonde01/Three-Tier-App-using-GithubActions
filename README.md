# Three-Tier Application Deployment Using Docker & GitHub Actions

A three-tier Student Management Application deployed using Docker, Docker Hub, and GitHub Actions CI/CD.

This project demonstrates how to containerize the frontend, backend, and PostgreSQL database separately, automate Docker image builds and publishing through GitHub Actions, and deploy versioned images on AWS EC2 or Killercoda without Docker Compose.

## Technologies Used

- **Frontend:** HTML, CSS, JavaScript, Nginx
- **Backend:** Python, REST API
- **Database:** PostgreSQL
- **Containerization:** Docker, Docker Network, Docker Volume
- **CI/CD:** GitHub Actions
- **Image Registry:** Docker Hub
- **Deployment:** AWS EC2 / Killercoda
- **Versioning:** Git Commit SHA

## Project Features

- Three-tier application architecture.
- Separate Dockerfiles for frontend, backend, and database.
- Automated Docker image builds using GitHub Actions.
- Automated image publishing to Docker Hub.
- Versioned Docker images using Git commit SHA.
- Runtime frontend API configuration using environment variables.
- Backend-to-database communication through a custom Docker network.
- Persistent PostgreSQL storage using Docker volumes.
- Container restart policies for improved availability.
- Deployment without Docker Compose.

## 1. CI/CD Pipeline Using GitHub Actions

GitHub Actions automates the Docker image build and publishing process.

### Pipeline Workflow

1. Developer pushes code to the GitHub repository.
2. GitHub Actions detects the push.
3. The respective workflow builds the Docker image.
4. The image is tagged using the Git commit SHA.
5. The image is pushed to Docker Hub.

### Docker Hub Images

```text
vishalkonde01/my-webapp-frontend
vishalkonde01/my-webapp-backend
vishalkonde01/my-webapp-database
```

### Image Versioning

Images use Git commit SHA-based tags.

Example:

```bash
IMAGE_TAG=dev-a82f91c7d123456789abcdef123456789abcdef12
```

## 2. Deployment on AWS EC2 / Killercoda

### Step 1: Create Docker Network

```bash
docker network create mynetwork
```

### Step 2: Create Persistent Database Volume

```bash
docker volume create pgdata
```

### Step 3: Set Docker Image Version

Use the actual image tag generated by GitHub Actions.

```bash
IMAGE_TAG=dev-a82f91c7d123456789abcdef123456789abcdef12
```

### Step 4: Pull Docker Images from Docker Hub

**Backend Image**

```bash
docker pull vishalkonde01/my-webapp-backend:$IMAGE_TAG
```

**Frontend Image**

```bash
docker pull vishalkonde01/my-webapp-frontend:$IMAGE_TAG
```

**Database Image**

```bash
docker pull vishalkonde01/my-webapp-database:$IMAGE_TAG
```

Verify downloaded images:

```bash
docker images
```

## 3. Deploy PostgreSQL Container

```bash
docker run -d \
  --name my_postgres \
  --network mynetwork \
  --restart unless-stopped \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=CHANGE_ME_TO_A_SECURE_PASSWORD \
  -e POSTGRES_DB=mydatabase \
  -v pgdata:/var/lib/postgresql/data \
  vishalkonde01/my-webapp-database:$IMAGE_TAG
```

Check PostgreSQL logs:

```bash
docker logs my_postgres
```

Wait until PostgreSQL is ready:

```bash
until docker exec my_postgres pg_isready -U admin -d mydatabase; do
  sleep 2
done
```

### Connect to PostgreSQL

```bash
docker exec -it my_postgres psql -U admin -d mydatabase
```

If your custom database image does not contain the `psql` client, use a separate client container:

```bash
docker run -it --rm \
  --network mynetwork \
  postgres:16 \
  psql -h my_postgres -U admin -d mydatabase
```
